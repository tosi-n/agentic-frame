# Daily content

Create one coherent daily story with channel-native versions and a measurable next action. A viral reference is a creative hypothesis, not proof of product fit or sales. This skill coordinates existing capabilities; it does not supply a scheduler, analytics account, or media-generation service.

## Establish durable context

Use [campaign context](references/campaign-context.md) to record the goal and product-specific inputs in the project's own directory. Keep a stable goal/campaign ID through research, production and results. Do not turn a pilot's audience, offers or creative preferences into universal skill defaults.

Read the project's current marketing plan, product evidence, brand assets, approved offers, past content and feedback. Keep product-specific context in that project's marketing directory, not in this distributable skill. Treat old chats and scraped brand profiles as leads to verify. Resolve conflicting pricing, capabilities and destinations before putting them in publishable copy.

Record the audience, buyer task, primary conversion, destination, channel/account IDs, audience timezone, cadence, production budget and current authorization. Distinguish a free-signup story from a paid-offer story. Inherit explicit user preferences; avoid asking again for information already supplied. Draft useful work while missing connector access or publication details are resolved. Do not infer recurring execution or publishing authorization from a request to design the workflow.

Use [the operating contract](references/operating-contract.md) for saved records, distribution and measurement. Continue an existing campaign rather than creating a fresh disconnected plan each run.

## Choose today's story

Track performing posts as an ongoing input using the separately installed `content-trend-research` skill from `stimulir/managed-skills`, with Treg as the external search and tracking tool. Pass campaign context, prior snapshots, bounded collection policy and a durable output destination. Read its instructions before use. Consume its opportunity IDs, source evidence, momentum caveats and use/watch/reject decisions. It is not bundled here: if absent, consume an existing compatible report or supplied evidence and identify the missing research package; do not claim live monitoring from a saved list.

Review owned performance and actual customer questions first. Optionally use installed `search-demand`, `seo-content`, `creator-community-research`, or `competitor-ad-research` skills for the specific missing evidence; these are separate packages, not bundled dependencies. Read their instructions only when using them. Without them, use supplied evidence or available authorized research tools and name the limitation.

Choose a concrete buyer problem, the demonstrated product action that addresses it, and one CTA. Explain why this story deserves today's slot. If considering a trend, name the transferable format and reject unrelated audiences, invented capabilities, copied testimonials, or a hook whose payoff the product cannot deliver. Log rejection reasons so tomorrow's queue improves. Avoid repeatedly generating the same angle or already-posted asset.

Prepare a compact brief: audience/task, hook, proof, claim sources, offer/CTA, channel variants, hypothesis and primary metric. Offer hook alternatives when useful, but pick one primary variable per test. Compare against an identified baseline over comparable windows; do not call observational differences causal lift.

## Produce a daily pack

Reuse approved footage and designs before paying to regenerate them. Route the required work to the installed sibling skills:

| Need | Skill |
| --- | --- |
| Real product demonstration | `clip-capture` |
| Edit existing footage and captions | `video-edit` |
| Presenter-led video | `ugc-video` |
| Image or carousel assets | `static-ads` (adapt for organic content) |
| Editable motion graphics | `tesseract-motion` |
| Convert a supplied post to video | `post-to-video` |
| Inspect transcript and scenes | `video-audio-analysis` |
| Generated music, speech or video | `media-generate` |

Read each selected skill before execution. Dreamina is a separately installed supplement: use its live model discovery and quote workflow, and stay within the user's applicable spending authorization. An old render's credit approval does not fund future daily runs. Preserve native source resolution; an upscale does not create new captured detail.

Keep the core claim, proof and offer consistent across channels; adapt opening, length, crop, caption, link placement and CTA to each channel. Coordinated daily publishing need not mean an identical timestamp or identical copy. Use the actual connected channels, not an assumed list. Reserve long-form SEO content for a supported search intent rather than automatically producing a blog every day.

## Review and deliver

Present a review card with playable previews or readable copy, intended accounts, destination, proposed timing, production cost, evidence links and any unresolved gate. Check final media for legible UI and captions, exact speech, unsupported claims, private data, audio, rights and CTA accuracy. Distinguish a real product capture, a staged illustration, an AI presenter and a genuine customer testimonial. Never pass one off as another.

Record precise feedback (wrong audience, unsupported claim, visual mismatch, unclear proof, weak offer, duplicate) and revise the relevant part. Prioritize this small review queue over an unbounded volume of generic ideas. A pack requiring new capture is `needs_capture`, not ready to publish.

When scheduling or publishing is authorized, use the connector's inspected contract and reconcile its result as described in the operating contract. Otherwise deliver the local pack and its explicit readiness state. Finish with what exists, what was verified, what was actually scheduled/published and the next unresolved dependency. Do not claim that a skill file is a running daily service.
