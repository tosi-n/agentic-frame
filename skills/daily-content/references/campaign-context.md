# Campaign context

Store the filled context in the product's own marketing/artifact directory and read it on every run. This is the input to the general skills, not another product-specific skill. Preserve user changes and link existing authoritative plans rather than copying conflicting versions.

## Required decisions

- Identity: goal_id, campaign_id, product, context version/date, source plan.
- Goal: desired business outcome, primary metric/source and supporting engagement/activation measures. Add numerical targets only when supplied or explicitly agreed; unknown baseline remains unknown.
- Buyer: audience hypothesis, concrete task/pain, market/language and supporting evidence.
- Promise: product capabilities with dated evidence, current offer, destination, exclusions and forbidden claims.
- Voice and assets: brand/likeness rights, creative preferences, approved sources and real demonstration inventory.
- Channels: intended accounts and verified connection status, audience timezone and cadence; distinguish proposed from approved timing.
- Research: Treg watchlist/query scope, maximum posts/pages, freshness window, available prior snapshots, endpoint grants and applicable budget.
- Production/distribution: budget, permitted generation tools, review requirements and existing publication authorization.
- Runtime: durable artifact destination, scheduler status/run IDs if active and unresolved dependencies.
- Learning: baseline/report windows, attribution limits, chosen test variable and keep/change/retire decisions.

## Reusable workflow and optional interface

Use campaign context → Treg trend report + owned results → selected story → channel-specific production → review → authorized distribution → measured feedback. Preserve goal/campaign/opportunity/creative IDs through the handoffs.

When a UI is warranted, use the same state for six views: Trends (evidence and use/watch/reject), Today (candidate stories and selection), Review (preview/copy/destination/revision), Calendar (verified remote status/timezone), Library (reusable proof and rights), Learn (engagement, activation and attributable sales). A UI is optional; durable briefs and the existing publishing calendar can support the workflow first.

Keep product examples and competitor assessments in project documents. General skills own the procedure; the campaign context owns what success means for this product.
